# 架构与模块边界规范

## 总体原则
- 以仓库真实包结构为准；下列分层仅为职责约束，不要求重排现有目录。
- HTTP 层负责参数、协议和响应映射；业务编排位于 Service 或相应领域组件。
- 持久化组件负责数据访问；Provider 适配器负责外部模型协议与调用。
- 避免 Controller 直接操作数据库、跨层循环依赖及基础设施代码泄漏到领域逻辑。
- Controller 层主要处理参数基本校验，结构转换等轻量逻辑，主要业务逻辑放在Service层

## 架构变更要求
- 引入新模块、公共接口、数据库模式或第三方依赖时，说明动机、替代方案、兼容性和迁移风险。
- 不在功能实现中顺带进行大规模包结构调整。
- 需要强制执行的依赖边界可逐步落地为 ArchUnit 测试；未配置前不要假称已受工具保护。
