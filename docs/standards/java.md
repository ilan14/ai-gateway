# Java 编码与测试规范

## 通用约定
- 目标版本为 Java 25；遵循现有项目风格和工具链。
- 类名使用 PascalCase，方法和变量使用 camelCase，常量使用 UPPER_SNAKE_CASE，包名小写。
- 命名体现业务含义；避免不必要的接口、继承、工具类和抽象层。
- 不随意引入依赖；优先复用已有组件。
- 不使用无意义的 catch；异常应保留足够上下文，日志避免敏感数据。

## Spring WebFlux
- 不在 Reactor event-loop 上执行阻塞式 IO 或长时间计算。
- 不在响应式请求链路中随意调用 `block()` 或自行 `subscribe()`。
- 明确超时、取消、错误及正常完成时的资源所有权和清理路径。
- 并发 Permit 的获取与释放必须具有清晰的生命周期；防止重复释放和泄漏。
- 共享可变状态需要明确并发安全保证。
- 对重试、熔断、限流和取消之间的交互进行显式设计。

## 测试
- 优先使用项目已有测试框架；如使用 JUnit 5、Reactor Test，保持现有约定。
- 新功能覆盖核心正常路径、边界和关键失败路径。
- 并发测试优先使用同步原语、可控时钟或确定性调度，避免依赖 `Thread.sleep()`。
- 外部 Provider、Redis、MySQL 等集成依赖应明确使用 Mock、Testcontainers 或真实环境的范围。
- 不通过跳过测试、削弱断言或吞异常来使构建变绿。
- 新增或修改java代码必须增加或者补全单元测试。
- 涉及存储的单元测试使用h2内存数据库或者mock，不产生真实数据。

## 验证
- 首先识别仓库支持的 Maven Wrapper 和现有插件。
- 可参考 `./mvnw test`；格式检查和集成测试命令应以 pom.xml 实际配置为准。
- 不声称项目已配置 Spotless、Checkstyle、ArchUnit 等未核实的插件。
