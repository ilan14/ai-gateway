# 模型保护与限流

## 需求边界

面向多实例部署，入口先做全局限流，下游按供应商和模型限流，自动熔断和恢复。暂不包含调用方身份、配额计费、TPM、人工管理接口或动态修改配置。配置修改需所有实例同步发布。

## 执行流程

参数校验后，在会话写入之前原子检查熔断、全局额度、模型额度与供应商额度，通过后获取并发租约及半开探测资格。请求完成、异常或取消均释放租约；实例崩溃则等待租约过期回收。请求计数使用最近一分钟的滚动窗口，并发覆盖整个请求（包括会话处理），流式直到结束才释放。

所有保护键使用 `gateway:{protection}:` 前缀。统一 hash tag 保证 Lua 在 Redis Cluster 上可原子执行，代价是保护数据集中在一个分片。Lua 使用 Redis 时间避免各实例时钟差异。调用历史使用有过期时间的 Sorted Set，状态使用 Hash，并发使用租约 Sorted Set，半开资格使用带过期时间的 String。当前规模以一个 Redis 分片承载全局协调，需根据实际流量评估容量。

模型状态按 `provider:model` 隔离：无 `until` 为关闭；冷却时间未到为打开；冷却结束进入半开竞争，最多一个探测调用。探测成功清除旧窗口并关闭，失败重新打开。取消或下游 4xx 不产生成功探测结果，释放资格供后续请求重新探测。迟到的半开结果不能覆盖新探测状态。

## 统计与错误

只包围实际 Provider 调用记录结果，会话存储异常不影响模型健康统计。下游超时、连接失败、5xx、无 `[DONE]` 的流和流内错误计入失败。正常取消不计入失败。429 单独冷却，优先使用有效 `Retry-After`（秒或 HTTP 日期），否则使用配置值。

达到连续失败阈值，或时间窗口内样本数和失败率同时达标，则打开熔断。正常成功重置连续失败数；连续失败间隔超过窗口则重新计数。

本地限流返回 429，熔断、Redis 访问失败或续租丢失返回 503。保护错误使用 OpenAI 兼容的 `error` 对象；SSE 提交之后的保护错误发送错误事件。其他下游错误沿用原有处理。默认不切换到其他真实模型。模型参数缺省使用配置默认值；未知模型沿用 stub 兜底，并将请求中的模型统一为 stub。

## 配置

`gateway.protection` 默认 `enabled: false`。以下示例启用保护：

```yaml
gateway:
  protection:
    enabled: true
    global-rpm: 600
    global-concurrency: 100
    provider-rpm: 0
    provider-concurrency: 0
    rpm: 60
    concurrency: 10
    window-seconds: 60
    minimum-calls: 20
    failure-percent: 50
    consecutive-failures: 5
    cooldown-seconds: 30
    lease-seconds: 60
    timeout-seconds: 120
    models:
      "[deepseek:deepseek-chat]":
        rpm: 120
        concurrency: 20
```

RPM、并发参数为 0 表示不限制；供应商共享额度默认不限制，配置后按每个供应商独立计算。模型条目使用完整策略（未填写的字段使用代码默认值，而非继承自全局配置）；全局额度和供应商共享额度始终取根配置。半开探测数固定为 1。`timeout-seconds` 同时用于首帧等待与帧间空闲等待，不限制持续正常输出的流的总时长。租约每三分之一周期续租；续租失败终止请求。

所有实例必须使用相同配置、同一 Redis 和同一数据库编号。Redis 故障时拒绝新调用；释放失败依赖租约过期回收。保护功能对 mock 和 stub 同样生效，以便验证入口行为。

## 指标与验证

- `gateway.protection.rejected`：被限流或熔断拒绝的请求。
- `gateway.protection.results`：结果分类（0 成功、1 失败、2 下游限流、-1 不参与统计）。
- `gateway.protection.transitions`：打开、半开和关闭次数。
- 保留现有 Provider 延迟、调用结果和在途数指标。

单元测试使用 mock Redis、H2，不访问真实业务存储。上线前应在隔离环境验证多实例竞争、Redis 故障恢复及目标流量下的单分片承载能力。

本次实现另使用禁用持久化、仅监听临时 Unix socket 的独立 Redis 验证了 Lua 原子并发、全局与供应商共享额度、熔断、半开互斥及恢复、迟到结果和租约回收。该验证不访问业务 Redis，进程退出即清理；可运行 `python3 scripts/verify_model_protection.py` 重现（需本机安装 redis-server 与 redis-cli）。
